# Parser inventory

Transaction ingress uses the SDK/CometBFT transport boundary, with no custom
whole-transaction byte cap before SDK decoding. validateTransaction calls the
pinned SDK protobuf unmarshallers for TxRaw and TxBody (including Any envelopes)
before ValidateMessageWire checks individual module payloads. These initial
unmarshallers have no custom byte, depth, message-count, memo, auth, public-key,
bitmap or signature-size limits. Network request and block limits belong to the
configured SDK/CometBFT transport; direct decoder calls do not enforce those
transport limits. Module limits do not bound earlier envelope allocations.

After envelope decoding, module payloads retain their 32768-byte limit, depth 8
and schema-specific repeated-field limits. Finally the stock SDK TxDecoder
unpacks the full transaction and the SDK ante handler verifies authentication.
No removed authentication or envelope bounds have been restored. Authentication
wire formats and sign modes are entirely SDK-owned. Public module queries
validate addresses, salt and scope after the inherited ABCI/protobuf router;
transport request allocation limits remain the SDK/CometBFT boundary. Canonical
state ingress is limited to 16 MiB and rows to 32 KiB. Whole-state scans occur
only on genesis/export. Runtime scenarios, not this inventory checker, establish
actual decoder behavior and signature validation.

MsgRemoveProvider and MsgReplaceProviderOwner are explicitly allowed by
validateMessage, registered as SDK messages and routed through the generated
Msg service. Their payloads use the existing wire limits; signer authentication
and amino multisig thresholds remain in the stock SDK decoder and ante.

Generated validatorset codecs remain behind the transaction/genesis guards.
Validator field 5 records vacancy. Provider canonical JSON carries the matching
vacancy flag and at most 256 retired consensus public keys per founder slot.
These fields persist through export and are validated before genesis admission.
The optional retired_pubkeys field retains removed nonfounder identities in an
independent record under the same canonical JSON and 32768-byte record bounds.
Genesis rejects duplicate or malformed retirement histories, active reuse and
reserved founder sets that cannot be refilled. Public genesis validation and
collection expose an explicit --snapshot path with module and SDK checks;
default founding validation remains strict.
Reflection bindings are checked against their schema and exercised by
TestAllMessageAndQueryCodecs and TestBoundedTransactionRoundtrip. Query replies
are bounded products of keyed reads. Scenario inputs are synthetic and bounded
by their fixture constructors; local consensus uses an isolated directory under `_build/`.

`SDK` in a limit column means no independent local bound is asserted; that
stage is delegated to the pinned SDK. SDK/CometBFT transport limits still apply
on their respective network paths. Module limits apply after envelope decoding and
must not be interpreted as bounds on the earlier SDK unmarshallers.

The numeric allocation/work columns are conservative review budgets, not
measurements or claims about transitive SDK allocations. Tools only read
repository source or bounded generator output. No entry authorizes arbitrary
filesystem or network input. Inherited unchanged sites retain their declarations.
